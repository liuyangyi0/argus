# Argus 检测质量验收标准

> 版本：Phase 0 初版（2026-06-12）。这些数字是后续回归库和真实现场验收的判定线；Phase 1 跑出真实基线后，只能通过一次明确记录的评审来调整。

## 1. 验收范围

本文件只定义固定摄像头视觉异常检测的质量验收。Dashboard 可用性、训练/发布流程、权限与审计等链路验收仍以 smoke、单元测试和集成测试为准。

默认目标场景：

- 单节点边缘部署，每路摄像头独立计数。
- 摄像头固定安装，验收期间不得调整焦距、变焦、自动构图、云台角度或监控区域。
- 以 RGB 可见光视频为依据；不可见气体、红外热异常、声学异常不在视觉验收承诺内。
- 默认启用静态异物 / 场景变化检测；高速小物体、水渍/泄漏、烟雾/蒸汽/粉尘等专项能力只有在对应配置开启且素材覆盖时才纳入验收。

## 2. 通过线

| 指标 | Phase 0 目标 | 判定口径 | 最低样本量 |
| --- | --- | --- | --- |
| 负样本误报率 | ≤ 2 次/小时/摄像头 | 负样本视频中产生的误报事件数 ÷ 有效正常视频小时数 | 每个目标场景 ≥ 30 分钟，合计 ≥ 2 小时 |
| 静态异物召回率 | ≥ 95% | 标注事件窗口内至少命中 1 次有效告警即算 TP | ≥ 20 个事件，覆盖不同位置/尺寸/光照 |
| 静态异物触发延迟 | P95 ≤ 10 秒 | 从物体稳定进入画面到第一条有效告警的时间 | 同静态异物召回样本 |
| 高速小物体召回率 | ≥ 80% | 启用 `fast_motion` 时，标注事件窗口内出现 projectile 类告警 | ≥ 20 个事件 |
| 可见水渍/泄漏召回率 | ≥ 90% | 启用 `water_leak` 时，标注事件窗口内出现 water_leak 类告警 | ≥ 20 个事件 |
| 可见烟雾/蒸汽/粉尘召回率 | ≥ 90% | 启用 `plume` 时，标注事件窗口内出现 visible_plume 类告警 | ≥ 20 个事件 |
| 72h soak | 无进程崩溃；无持续内存增长；单路故障不拖垮其他路 | 连续运行日志、健康指标、告警记录和恢复事件 | ≥ 1 路真实摄像头，建议 ≥ 2 路 |

专项能力未启用或没有对应素材时，不允许在验收报告中声明该能力通过。

### 当前 production 发布契约（沿用严格门禁，不作能力分档）

上表 Phase 0 是历史检测研究/能力评估口径，不表示当前服务端可只凭该表执行 production。
当前正式发布统一使用更严格的完整能力门禁：静态与 projectile 各至少 20 个事件、各自召回
及 overall recall 均不低于 95%，至少 2 小时有效负样本，FP 不高于 2/h，P95 延迟不高于
10 秒，SceneGuard coverage 不低于 99%；高速源及有效回放不低于 59 FPS。还必须满足
baseline v3 严格解码、独立 source/session、精确模型/profile/artifact 绑定、独立人工审批和
可信的至少 72 小时 soak。具体以 `release_evidence.py` 的全部校验为准。

当前没有“仅静态版”的 production 快捷路径；即使关闭高速通道，也不能省略既有发布证据。
如未来要交付分档能力，必须先正式评审并版本化能力/验收契约，不能通过本轮工作流、CLI
参数或界面开关降低当前安全门。研究报告中不得把未覆盖的专项能力写成已通过。

## 3. 计数规则

误报按事件计数，不按帧计数。

- 同一路摄像头、同一根因、相邻告警间隔 ≤ 60 秒，合并为 1 次误报事件。
- 标注为 ignore 的时间段不计入分母，也不产生 FP/FN。
- 负样本分母只包含有效正常视频时长；摄像头断流、严重遮挡、人工调整镜头、启动预热期不计入分母。
- 正样本召回按事件窗口计数。一个标注事件只计 1 个 TP 或 1 个 FN，多次重复告警不提高召回。
- 有效告警必须满足 category / detection_type 与目标类型一致，并带有可追溯证据：时间、camera_id、bbox 或区域、score、evidence_summary、Replay 片段或关键帧。
- 现场人工确认与离线评估冲突时，以保存的原始视频、标注文件和告警记录复核，不以口头判断覆盖数据。

`scripts/evaluate_video.py` 输出帧级 FP/FN；正式汇总使用 `scripts/run_regression_suite.py` 把连续 FP 帧按上述 60 秒规则聚合为误报事件，再换算 FP/小时。

## 4. 物理边界

满足以下边界的场景才属于承诺范围：

| 边界项 | 承诺范围 | 不承诺范围 |
| --- | --- | --- |
| 摄像头稳定性 | 固定机位；轻微环境振动允许，但画面主体位移 P95 ≤ 8 px | 手持、频繁云台转动、自动构图/自动变焦、镜头被碰后未重新采集基线 |
| 分辨率与帧率 | 采集分辨率 ≥ 1280×720；验收推荐 1920×1080；有效分析帧率 ≥ 10 FPS | 低于 720p、长期低于 10 FPS、严重丢帧或编码损坏 |
| 光照 | 目标区域可见，无遮挡；验收记录中需写明照度或“日间/室内稳定光”等可复现场景描述 | 目标与背景不可分辨、强眩光直射镜头、频闪导致目标形状不可见 |
| 静态异物尺寸 | 目标稳定可见 ≥ 3 秒；bbox 短边 ≥ 32 px 且面积 ≥ 1500 px² | 小于尺寸下限、只出现 1-2 帧、完全贴近背景且人工也难以分辨 |
| 高速小物体尺寸 | 目标在事件窗口内至少 3 帧可见；长边 ≥ 20 px | 单帧闪现、严重运动模糊到无法定位 |
| 可见水渍/泄漏 | 画面能看到滴落、流痕、湿斑扩张或反光变化 | 管内泄漏、透明无痕液体、仅由传感器才能发现的泄漏 |
| 可见烟雾/蒸汽/粉尘 | 画面能看到持续扩散的可见羽流 | 无色气体、完全被背景蒸汽覆盖、只由气体传感器才能发现的异常 |
| 人员与维护活动 | 负样本可覆盖人员正常经过，但不应长时间遮挡目标区域 | 长时间施工、换景、镜头清洁、遮挡超过 20% 画面 |

超出边界的场景可以记录为风险或后续需求，但不能作为当前版本不通过的唯一依据。

## 5. 验收产物

每次正式验收必须留下以下文件或记录：

- 原始视频或视频清单，包含 camera_id、分辨率、FPS、录制时段和物理场景说明。
- 标注 JSON，使用 `positive_ranges` / `ignore_ranges`，帧号或秒数均可，但必须与视频一一对应。
- 离线评估输出：`evaluate_video.py` 的 JSON/Markdown 报告，或后续回归套件汇总报告。
- 回归套件输出：`scripts/run_regression_suite.py` 生成的 `regression_report.json` 与 `regression_report.md`。
- Dashboard 告警导出或数据库快照，用于复核 FP/TP/FN 和 evidence 字段。
- 一页 go/no-go 结论，逐项引用本文件的指标并给出实际数字。

## 6. 调整规则

Phase 1 拿到真实回归库基线后，如果发现目标过严或过松，必须同时提交：

1. 调整后的 `docs/acceptance.md`。
2. 修改原因和基线数字。
3. 受影响的部署边界或能力范围。

不能只改阈值或代码而不更新验收标准。

# 公开仓库信息卫生

- 项目介绍、页面标题、报告和注释使用通用视觉异常检测表述。
- 实际主机、账号、地址、连接别名、密钥位置和部署清单保存在仓库外的私有配置中。
- 文档示例使用 `.example` 域名或 `192.0.2.0/24` 文档地址，不代表可连接的设备。
- 私钥、证书、环境变量文件和本地审计备份不得提交；`.env.example` 只能包含空值或占位符。

## SSH 公钥安装工具

`scripts/setup_remote_sshkey.py` 没有默认主机、账号或密钥文件名。使用前显式设置
`ARGUS_REMOTE_SSH_HOST`、`ARGUS_REMOTE_SSH_USER` 和 `ARGUS_REMOTE_SSH_PUBKEY`；
可通过 `ARGUS_REMOTE_SSH_PASSWORD` 提供密码，否则交互输入。只允许提供公钥，
目标主机必须已通过独立渠道核实并存在于 `known_hosts` 中。不要将真实值写入示例。

## 历史清理后的协作

历史重写会改变提交 SHA 和签名。协作者应重新克隆，不能将旧分支直接 merge 或
强制推回远端，否则会重新公开已移除的数据。旧克隆中未提交的工作先保存在本机，
再逐文件迁移到新克隆；迁移前扫描工作文件和拟提交差异，不自动套用整个旧历史。

本地备份与审计资料放在被忽略的 `.local-validation/` 中，不得上传。
GitHub 的只读 PR 引用、旧 SHA 页面和缓存不受普通分支强推控制，必要时需要
联系 GitHub Support；不能仅凭分支扫描通过就宣称这些缓存已被删除。

## 防回归

`tests/lint/test_publication_privacy.py` 扫描公开工作文件的受限表述、部署身份和完整
私钥块，错误仅输出文件名和规则名，不输出命中内容。该检查不运行模型或视频处理。
历史清理仍需对所有远端分支、标签及提交内容另做独立审计。

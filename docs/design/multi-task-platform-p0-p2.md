# 多分析任务平台：P0—P2 领域契约与迁移边界

日期：2026-10-23。本文描述本次增量改造的边界，不是新算法或生产能力验收报告。

本文保留 P0—P2 阶段记录；后续已新增的旁路执行和数据工作流见 [P3—P6 实现与使用说明](multi-task-platform-p3-p6.md)。该增量不等于新任务已经通过生产验收。

## 目标与非目标

将“相机等于一套异物 Pipeline”逐步改为“一个采集源向多个独立任务供帧”。本轮首先建立任务身份、模型制品与部署状态分离、唯一采集所有权及有界多订阅运行基础。

现有完整异物检测注册为 `legacy_anomaly.v1`，保持其检测、SceneGuard、基线、校准和发布政策。不能把兼容模板拆成静态或快速子任务，以省略已有验收证据。

本轮不开放任意任务创建、通用模型文件上传即运行、图形化算法编排或第二条 production 发布入口。独立工作进程、异构模型执行包发布、自动采集/标注/训练闭环和姿态、安全帽等任务属于 P3—P6；本轮新增底座不表示这些能力已经交付。

## P0：冻结的领域划分

| 概念 | 权威数据和职责 | 本轮实现边界 |
| --- | --- | --- |
| 摄像头源 | 设备连接、源会话、重连代次、原始帧和预览供给 | 唯一采集所有权；任务不能竞争读取设备 |
| 任务模板版本 | 功能、采样契约、模型角色、输入输出、安全和验收要求 | 仅声明 `legacy_anomaly.v1`，不声称新模板可生产运行 |
| 分析任务 | 摄像头、模板、稳定任务身份、运行生命周期 | 原相机映射确定性 legacy 任务 ID；与后台作业分开 |
| 任务配置版本 | 不可变配置快照及 SHA-256 | 首次登记快照，不在每次启动时用 YAML 覆盖；legacy 配置执行权仍在既有配置服务 |
| 模型制品 | 不可变模型身份、能力与适用范围，不含运行状态 | 对通过既有证据核验的 legacy 注册记录建立独立投影；保留 camera scope |
| 任务部署 | 期望身份、注册授权、运行时已应用身份 | 本轮为只读 legacy 投影；既有 `ModelReleaseService` 是唯一发布写入者 |
| 执行包、数据集与训练配方 | 模型组合、规则、校准和数据血缘 | P3—P6，尚未开放 |

任务 ID 由摄像头 ID 的独立命名空间确定性生成，不能靠模型文件路径、数组位置或 UI 名称识别任务。缺失、冲突或损坏的任务身份应显式失败，不能静默选中第一个任务。

### 必须分开的状态

- 摄像头源正在运行，不代表某个任务正在检测。
- 注册记录 active/production，不代表当前进程已加载该模型。
- 运行时核验了模型制品身份，不代表 SceneGuard 已放行。
- 读取失败或没有运行时，返回 unknown/明确不可用；不伪装成正常、已停止或零任务。
- `desired_artifact_id` 是注册授权投影，`applied_artifact_id` 在缺少任务级运行核验/提交协议前保持空。当前观测模型单独放在 runtime 字段。

## P1：加法迁移与单一权威

新增任务、任务配置版本、模型制品和任务部署表。启动装配执行一次性 legacy 登记；重复执行不重写已有配置。数据库锁和事务处理并发首次登记，完整性校验保护身份及配置摘要。

`sync_legacy_model_projection` 是显式生命周期动作，不是 GET 的副作用。它复用既有 production 证据验证，核验前后比较权威注册记录，拒绝发布并发引起的陈旧投影。旧短 model hash 不能冒充完整 artifact SHA-256。

现有模型发布表、每相机生产唯一约束、release revision、审批身份和持久化证据继续有效。新表不反向修改旧模型 active/stage，也不扫描文件系统替代 registry 授权。迁移失败须保留旧数据并报告；修复问题后幂等重试。

本轮配置快照只是迁移和完整性依据，不接管现有 UI 的配置写入；将来切换到任务级配置权威必须配套迁移和明确交接，不能出现两个配置写入口争夺同一对象。

`current_revision` / `config_sha256` 表示导入快照版本和摘要，不是当前生效配置或已经应用的任务版本。首次导入后，既有配置编辑仍可能改变实际运行配置；本轮不把两者强行同步或宣称 runtime 已应用该快照。任务级配置写入权威与 applied task revision 的完整协议留到 P3 收敛。

部署投影也有时效性：GET 可只读比较现有 legacy registry 的版本、release revision 和身份，变化后标记 `stale`，不能继续把旧授权快照显示成当前有效授权；该检查不更新生产状态、不自动同步或发布。

ORM 字段及独立索引遵循现有自动迁移守门。旧数据缺少的任务、PTS 或审批证据不能补造；不修改任何源视频。

## P2：采集与任务运行边界

### 单次采集与多订阅

采集源独占底层 capture，向帧分发组件发布原始帧。任务通过独立订阅读取，不再从同一 destructive-read 槽竞争取走帧。

- 最新帧策略允许覆盖积压，适用于现有持续异常链。
- 有序有界策略用于后续时间敏感任务，记录丢帧/过载，不假装满足高频任务的采样要求。
- 慢任务不能阻塞采集和其他任务；所有队列有界。
- 帧像素和原始身份不可被订阅者互相改写；可变处理元数据属于任务自己。
- 停止任务不等于停止源；停止摄像头源时则须明确处理其所有订阅任务。

有序窗口一旦丢帧即锁存 `sampling_insufficient`，不再计算或提交结果，必须显式停止/启动恢复；不能把不完整窗口当成正常检测。声明为有状态的处理器必须提供 reset，在任务启动、源会话/代次或部署 revision 改变后先清空时序状态。

任务处理器的慢计算不持有采集源锁；结果提交回调必须是短操作，磁盘、网络和数据库交付放在接受点之后。本轮 legacy 告警保留原 dispatcher：在源代次检查下接受结果，释放源锁后交付。已接受事件不会因随后重连而撤销，重连前尚未被接受的迟到结果会拒收。

相机停止必须确认任务和源均完成清理，才能注销旧任务并允许同一任务 ID 绑定新源。失败时保留旧身份和资源所有权供重试；注销后的旧 runtime 引用不可重新启动。重连保留原最大重试数/指数退避、声明源与运行源身份，兼容视图继续提供 FPS、分辨率、像素格式和降级诊断。

源身份保留源会话、源代次、帧号和已有时间元数据；无法取得的 PTS/time base 保持缺失，不以任务执行计数补造。真实视频时间对齐仍须在后续硬件/视频回归中验收。

### 独立运行和迟到结果

任务运行状态与源状态分别读取；启动、停止及重启产生新的任务代次。工作结果只允许影响对应的源代次、任务代次和模型部署身份，过期结果不能回写当前状态。

本轮先由 legacy 适配层接入现有处理入口，保留原检测逻辑。新增多任务基础设施使用模拟消费者证明订阅隔离，不以模拟通过宣称两套真实模型已满足并发吞吐。

资源隔离不等于 GPU 容量无限。独立计算进程、资源准入、训练维护窗口和多模型并存容量属于后续阶段；不能用本轮线程/订阅隔离承诺“训练期间监控不受影响”。

## API 和界面

新增只读接口，采用现有鉴权和统一 `{code,msg,data}`：

| 接口 | 返回 |
| --- | --- |
| `GET /api/analysis-task-templates` | 已实现兼容模板及明确的创建能力限制 |
| `GET /api/analysis-tasks?camera_id=…` | 任务身份、配置摘要、部署授权投影、独立任务/源状态 |
| `GET /api/analysis-tasks/{task_id}` | 单任务状态；不存在返回 404 |

所有接口要求 `read_cameras`，不公开相机源凭证、模型绝对路径、原始配置或 SDK 异常。GET 不登记任务、不同步制品、不启动源、不加载模型。

`/api/tasks` 保持后台作业语义。现有按 camera_id 操作的接口仍只代表明确的默认 legacy 任务；未来出现歧义时必须返回冲突，不能选第一个任务。旧相机 stop 的整源停止语义与新任务级停止不是一回事，不能混用。

CameraDetail 新增只读任务面板，保留既有播放器和业务操作。面板区分加载、失败、无任务和刷新过期数据，60 秒 REST 对账；换相机、卸载后的迟到响应不能污染页面。期望模型、注册授权和实际运行观测分别展示，不提供绕过旧发布门禁的按钮。

## 验证要求和完成边界

本机仅运行普通功能和模拟测试，不运行真实训练、识别、摄像头采集或源视频处理。

本轮普通/模拟验收重点：

1. 空数据库、旧数据库迁移、重复启动、并发首次登记、提交失败重试、摘要损坏拒绝。
2. 注册授权投影与运行时加载状态不混淆，不产生第二个发布写入口。
3. 一个源被一个 reader 读取，多个模拟订阅不抢帧；慢消费者、有界丢帧、任务启停和源重启隔离。
4. 源帧身份和任务元数据隔离，迟到结果不得污染重启后的任务。
5. API 访问权限、404/500/503 envelope、无隐私泄漏和无 GET 副作用。
6. 任务面板错误、空态、切相机竞态、卸载清理和 REST 对账。
7. 相关既有安全门、相机管理、模型发布、告警、播放器和迁移回归。

上述测试不能替代旧异物链真实视频输出等价回归、CUDA 模型恢复、实际多任务吞吐或 72 小时可信 soak。未经原有全部发布门禁通过，production 仍不得放行。具体执行结果应以本次验证记录为准，不在设计文档中预先宣称通过。

### 本机验证入口

普通后端与平台模拟测试统一使用 `scripts/run_local_functional_tests.py`，其执行保护禁止真实模型引擎、训练和摄像头/视频采集。本轮新增 `--suite platform`，覆盖任务存储、API、FrameHub、运行时、Manager 接线和跨模块对抗回归。前端使用 `npm run test:unit` 与 `npm run build`，契约使用 `scripts/generate_openapi_types.py --check`。

非权威部署投影发生并发冲突或同步失败时，不得关闭整个 Dashboard 或增加一条相机启动授权门；保留未同步/过期快照并记录诊断，下次显式生命周期动作重试。任务身份完整性失败仍阻断对应任务，Dashboard 保留维修入口；列表不能将登记失败伪装成正常空数据。

# 通用目标检测：事件、复核、发布档案与训练执行

日期：2026-10-26；训练资源与调度接线更新：2026-10-28。本文记录代码交付边界，不是生产批准或真实模型验收报告。

本轮范围经确认仅限验证态，不新增通用目标检测的生产验收契约；下列 NO-GO 原因是保留边界，不应通过填写档案或模拟测试消除。

## 安全边界

- 只扩展 `object_detection.v1` 的验证态事件；其它任务和 legacy 原发布入口不变。
- 所有当前任务运行仍为 shadow。工作进程返回的 `production_allowed` 不能授权生产告警。
- 发布档案的独立人审只确认档案，不能代替已批准的模板契约、可信评估和运行时 applied 收据。当前 `authorize_event()` 拒绝生产，readiness 为 NO-GO；尚未实现生产 apply。
- 不改源视频，不新增采集 reader，不放宽 SceneGuard、baseline v3、完整校准、独立审批或可信 soak。

## 已实现的控制链

### 检测结果到验证事件

`TaskExecutionManager` 在已有任务/源/部署栅栏内仅非阻塞入队。独立、有界事件 worker 核验配置、模型角色及 SHA、执行身份、请求序号、源会话/代次/帧身份，然后按类别、空间关联、持续时长和冷却生成可去重的事件。

数据库事件与 outbox 同事务。失败保留原事件身份对账；响应丢失不换事件 ID，也不丢失已保存的人审备注。独立 outbox 投递不依赖 legacy 产生告警，拒收保持 pending、保序重试；接收端仍须按事件 ID 去重。

首次部署必须核对 applied 回执后才进入时序累计，避免回执迟到提前消耗首个事件的冷却期。队列丢帧使用任务独立、有界的连续性令牌打断持续确认；旧队列包、旧源代次和旧部署不能借重试恢复有效。

队列满、证据编码失败、存储配额不足都有独立状态，不阻塞相机或同源其它任务。此版本不把没有事件等同于“已识别正常”。

### 事件复核与回放

- 事件支持确认、误报和解决；提交携带 revision，保留备注历史，拒绝旧页面覆盖新状态。
- 保存原帧身份对应的派生 JPEG，并校验 SHA。缺失或被替换时明确不可用。
- REST 对账与实时更新都会重新核验当前选中证据；迟到响应不能恢复已失效关键帧，人工备注草稿保留。
- 回放协议明确 `keyframe_only`、`video_available=false`，不将单张关键帧伪装成完整录像。
- 界面区分采集序号与原始源帧号；未知原始帧号、PTS 保持未知，不补造。

### 发布档案

档案冻结任务配置、执行包、部署修订、模型及证据文件摘要。支持申请、独立复核、拒绝、撤销及幂等重试。申请人不能自批；共享 token 和关闭认证不能提供个人审批身份。

更新证据会保留旧复核记录与备注，但使旧结论失效；任务/部署或文件摘要变化后必须重新核对。202 只表示申请被登记，不代表运行时已经切换或生产已放行。

### 标注 v2 回传

`annotation-export` 返回任务标签体系、源会话、帧号、PTS、图片尺寸和 SHA、报告摘要。`annotation-import` 要求完整匹配这些身份，仅生成 `needs_review` 建议，保留人工备注并使旧数据集/训练批准失效。

v1 仍可读取和导出；不再接受外部 `origin=human` 冒充人工批准。个人 `review` 接口仍独立保留。这里是可核验的交换协议，不声称已实际上传 CVAT/FiftyOne 服务或完成外部服务验收。

### 受控训练执行

训练执行以数据库为权威，冻结已批准的数据包、任务、参数、基础权重、执行确认身份；支持队列、资源等待、运行、取消、失败、完成及未知结果对账。

真实 worker 使用显式 spawn、惰性 SDK 导入和 CUDA，不在 import、页面加载或 GET 时启动；固定 YOLOv8 检测配方与经核对的 SDK 版本，禁止自动安装/下载及静默 CPU 回退。完成结果仍为 candidate，必须另行登记并做旁路评估，不能自动上线。

完成任务返回的 candidate 可原样交给已有候选登记接口。带 SHA 的训练产物先校验文件和标签身份，再写导入意图；唯一模型登记服务再次核对预期 SHA，防止预检后替换文件污染登记回执。结果不明时对账同一候选请求，不猜测成功或换请求重训。

`.pt` 可能携带 pickle；请求提供的 SHA 不是来源批准。`task_training.trusted_base_models` 默认空，只有运维人员在服务端预置且在启动配置中登记的可信权重可进入执行边界；这不是普通 `operator` 角色可自行批准的操作。Dashboard 已接入该启动配置、资源准入和生命周期调度器，但默认配置继续拒绝真实训练；配置/接线与普通模拟测试通过都不能写成真实训练已完成。

`TaskTrainingCoordinator` 只在显式资源准入持有 lease 后启动 worker。第二个协调器受数据库 OS 锁约束；未知启动、未知写入或清理失败保留资源/所有权，不猜 PID、不盲重训，也不因关闭 pipe 就断言进程已退出。

### 训练资源配置与生命周期接线（2026-10-28）

`configs/default.yaml` 的启动默认值如下；它与 legacy `retraining` 配置互相独立：

```yaml
task_training:
  enabled: false
  maintenance_approved: false
  resource_mode: exclusive_maintenance
  device: cuda:0
  minimum_free_memory_mb: 4096
  poll_interval_seconds: 1.0
  trusted_base_models: []
```

每条可信基础模型配置包含 `model_id`、`name`、`relative_path`、`artifact_sha256`。路径必须是 `storage.models_dir` 下规范的相对 `.pt` 标识，拒绝绝对路径、路径穿越、非规范分隔符和其它后缀；SHA 必须为精确的 64 位小写十六进制。模型 ID 和路径不能重复。配置校验只验证身份格式，不读取、哈希、加载或反序列化模型；实际提交/执行仍须核对已预登记的路径与 SHA，以及运行时文件身份。用户提交的 SHA 仅绑定请求内容，不能把未知来源的 pickle 变为可信。

服务构造时复制这份配置，普通 HTTP 接口不能增删信任、修改设备、批准维护或启用调度；通用配置重载拒绝该段漂移，启用与信任变更需要运维修改启动配置并重启。`enabled: true` 而 `maintenance_approved: false` 是合法等待配置，不会因调度线程存在就自动获准训练。

- 应用 lifespan 仅在显式启用后启动一个串行调度线程，按配置周期处理持久化队列。每个持久化 SQLite 数据库由一个 OS 锁 owner 协调；每次只准入一个作业，同一任务仍只允许一个未解决训练执行。构造、模块导入、页面加载和 GET 不启动 worker。
- 资源模式当前固定为 `exclusive_maintenance`，只接受可明确识别的单张 NVIDIA GPU `cuda:0`。进入维护前核验应用内所有在线、启动中、预加载/准备中及清理未确认的模型消费者；不能确认空闲时任务保持资源等待。维护互斥在进程内持续生效，普通配置重启后才退出；源采集/预览不等于模型计算，不会因此被改写为推理就绪。
- 维护批准必须由运维显式提供，系统不为训练自动停止在线推理。维护启动不加载在线模型，禁止冲突的 legacy 模型计算/配置写操作，并保留独立源/预览路径；无 Dashboard 的维护启动不提供另一条调度旁路。需要先停用并清理现有模型消费者，再按批准的维护配置启动。
- 正常装配的 `CameraManager` 在模型加载或进入维护前还须取得 `~/.argus/runtime/cuda0-compute.lock` 的 OS handle 锁。同一系统用户的不同 Argus 数据库/进程共用此路径，当前保守拒绝第二个计算实例；持有中的源/预览不占任务计算槽。锁不以 PID 文件、超时或 GC 过期；释放未知保留强引用，共享模型或清理残留不提前释放。它不覆盖其他系统用户或未接入 Argus 的外部计算程序。
- CLI 和带 legacy 后台执行器的装配保守持锁直至 OS 进程退出；旧调度器尚未提供覆盖所有在途计算的正向清理租约，不能因为相机列表为空或 Dashboard 关闭就提前释放。禁用训练调度也不代表已有孤儿训练退出；关闭时重新核对持久化未解决执行。
- 命令行退出显式通知 Uvicorn 执行 lifespan 关闭，再有界重试训练清理；未确认时不声称成功、不显式销毁仍可能被后台 owner 使用的数据库。训练维护控制进程不为启动日志初始化 CUDA，GPU 探测只用于实际准入。
- 准入时执行有界 GPU 观察，拒绝设备/进程状态不可确认、已有计算进程或空闲显存不足。`minimum_free_memory_mb` 只是准入阈值；应用互斥、进程观察与 lease 都不是 OS 显存硬配额、GPU 分区或对外部程序的强隔离。`memory_limit_enforced=false`，不能用缓存的 ready/leased 推导并行容量或保证外部程序随后不占卡。
- 队列与等待状态可以取消；已启动的执行需要先确认子进程清理，取消请求不是退出证明。重启后的 `running`/`cancelling` 孤儿先进入 `reconciling`，完整对账优先于新作业，不按队列顺序漏过较晚孤儿；只有明确的退出观察才可收敛为失败/取消。未知启动、提交、PID 状态或清理失败保留未解决记录以及进程内 lease/owner，不杀猜测的 PID、不自动重训、不伪造完成；退出或断连本身也不生成训练成功证据。
- 未解决运行记录会在重启时继续隔离在线模型计算，即使本次关闭训练开关也不能绕过；关闭会停止新调度并有界等待清理，清理不明继续显示受阻，需要对原执行身份进行运维对账。修改配置或另起调度器不能代替这种对账。

`GET /api/analysis-tasks/{task_id}/training-capabilities` 需要 `manage_training`，返回经过类型约束的启动配置、服务端可信基础模型选项、调度器和资源缓存快照。缺失运行时显示 disabled，读取失败显示明确原因码；不从配置启用值补造活跃状态，不泄露绝对路径或原始异常。GET 不读模型、不计算制品 SHA、不探测 GPU、不迁移状态，也不授予维护、资源或生产权限。前端按需读取后只能从服务端列出的基础模型身份中选择，提交仍携带既有 `base_model_path` 与 `base_model_sha256`，不能通过手填路径新增信任。

### 训练资源接线：第二轮对抗审查（2026-10-28）

本轮对真实训练流程只做静态审查，对并发与故障使用普通／模拟测试；没有调用真实模型或训练 SDK。

- 启动信任配置成为不可扩大的上限，运行期间仅允许撤销或恢复原有身份，不能通过公开映射增加路径或改绑摘要。提交、认领、启动授权和完成提交均重查信任与批准；数据库行的任务、工作流、创建人也必须与冻结请求一致，旧回执不允许借机改绑。
- HTTP 同时核验启动配置、工作流服务、训练服务、运行时和准入器是否属于同一装配；任务/工作流/作业作用域读取完成后重新核对个人身份，失配即拒绝，而非继续使用旧读取结果。
- 同一管理器下的多个准入器共用一个训练槽，探测前即占用，按精确租约身份释放；另一应用关闭时也须看到该占用。未知数据库状态不再被当成空闲。
- 子进程先持有独立 worker OS 锁，再报告精确 execution 身份就绪，只有收到父进程授权才进入计算。父主锁消失不证明子进程退出，新的主锁申请还要核验 worker 锁；子锁保留到 OS 进程退出，不以 SDK 返回替代退出证明。路径由当前管理器装配，不从训练请求读取。
- 等待就绪在数据库写事务外，最终授权在当前请求/批准/信任的短事务内。取消或关闭在等待中到达时不得继续授权；晚到结果与无效 IPC 进入失败/清理流程，不无限重试读取，也不原样披露 worker 任意消息。
- `is_alive=None`、OS 句柄关闭未知、终态提交后资源释放失败等情况继续保留所有权，缓存状态必须显示清理未确认。OS 锁不再先 unlock 再 close；清理重试不重复启动训练。
- 维护状态属于管理器的进程级事实，不能通过重新装配应用、换数据库或旧启动快照绕过。旧独立计算请求一旦获准，其缓存/后台工作须按保守边界持有排斥，不能仅根据 HTTP 已返回允许训练；无权威计算管理器的重导出、重校准、模型比较与 backbone 升级拒绝执行。
- 本机测试守卫扩展到会创建进程的 `SpawnTrainingWorker.prepare`：仅显式假 context 能测试准备逻辑，真实准备和训练入口均禁止。独立的真实 Python IPC/OS 锁子进程测试不含模型执行路径，并禁止模型 SDK 导入。

以上仍是同用户 advisory 互斥和应用内授权，不是 OS 显存硬隔离；新任务只允许验证态，生产安全门与源视频不变。

- 原始帧身份采用严格类型的完整契约。帧号、PTS、time base、源会话和采集时间不能被布尔值、等值浮点数或缺半边的时基替代；首帧与当前帧核对同源及单调采集顺序，不把可能校时跳变的墙钟当作单调时钟。事件摘要同时绑定证据 JPEG SHA、任务配置、不可变执行包与模型映射，派生 PNG 保留自身 SHA 和原始事件摘要。
- 同一源帧在单轮及多轮采集中均去重。新事件不能通过换事件 ID 反复加入同一帧；同帧出现不同 PTS 等身份时明确失败。最终入样再次核对持久化的事件上下文和原始身份。历史证据可在原收据下重试完成，不要求当前相机仍运行；精确重放不重写人审备注或预标注。
- 线程启动／退出结果不明时继续保留采集所有权；只有明确停止及清理证明才允许最终回执。每任务采集互斥，并在数据库写事务内限制未结束采集；本服务持有的未知清理状态也继续占用名额。该限制不是分布式 GPU 或全系统磁盘配额证明。
- 手工候选与训练候选使用同一会话内请求账本和提交所有权；组件关闭不能解除在途提交。冻结请求、原始版本、个人身份、交接摘要和批准摘要一起保留，未知结果只使用原请求对账。服务端分别保存原请求身份与规范化制品描述，登记期间多次复核个人权限，失权不返回成功。待对账响应与完成回执均校验请求、制品和审批上下文，历史缺少身份时不补造。
- 导出清单在下载或写入摘要前检查相机、任务、工作流、配置和账号代次，并核对响应绑定。旧任务迟到响应不得污染新任务；返回同一工作流也不能复活旧操作。配置变化会丢弃结果，但仍释放原操作的忙碌状态。原人工备注和未提交审核内容不被候选登记刷新覆盖。
- 录像读取拒绝链接／重解析与硬链接；目录及打开后的文件分别核验相机范围。流式响应在发送失败、取消或尚未开始迭代时仍释放文件。文件访问移出事件循环；未封存录像仅提供弱 ETag，带 If-Range 的请求保守返回完整响应，普通合法 Range、suffix Range 与 416 保留。

以上验证范围仅为普通功能和模拟故障，不代表真实模型效果、连续事件录像、GPU 容量或生产发布验收。源视频及生产安全门保持不变。

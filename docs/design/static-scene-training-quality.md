# 固定机位静态场景的训练质量适配

日期：2026-10-25。本文定义训练前质量判断的适配范围与验证边界，不构成训练确认、场景审批或生产发布证明。

## 1. 结论与问题来源

固定机位的正常场景可以长期保持相同布局和稳定照明。全图平均亮度变化小、感知哈希相近，说明观测到的外观变化有限，不能单独推导出数据损坏、模型不可训练或摄像头已经冻结。反过来，大量相似图片也不能证明正常工况覆盖充分、样本独立或模型已经满足业务目标。

当前代码存在两套相似命名但不同含义的训练前规则：

| 入口 | 近重复指标 | 亮度指标 | 原处理方式 |
| --- | --- | --- | --- |
| `ModelTrainer._validate_baseline_quality()` | 全部图片的 8×8 平均哈希，以汉明距离聚合近重复图片，计算图片比例 | 每张图片全图灰度均值的标准差；`<= 2.0` | 近重复率 `>= 80%` 或低亮度波动均作为训练错误 |
| `TrainingValidator.validate_baseline()` | 最多抽取 50 张图片，缩小为 64×64，统计相关系数达到阈值的图片对比例 | 全图灰度均值的标准差；`< 2.0` | 两项均作为警告 |

二者不仅错误/警告等级不同，重复“图片比例”和“图片对比例”也不能直接比较。相同的 `80%` 不代表相同统计量，边界 `2.0` 的判断也不一致。把其中一个入口的结果当作另一个入口已经通过，会产生流程漂移。

正常图像训练的目的不是强行让相机画面变化。PatchCore 使用正常图像的局部特征构建代表性记忆库，这为“稳定外观不应被全图变化率一票否决”提供了方法背景；论文中的数据集成绩并不证明 Argus 的办公室场景、模型或门禁已经达标。[PatchCore，CVPR 2022](https://openaccess.thecvf.com/content/CVPR2022/html/Roth_Towards_Total_Recall_in_Industrial_Anomaly_Detection_CVPR_2022_paper.html)

## 2. 将不同问题分开判断

- 数据完整性：文件、来源、源会话、帧号与 PTS、解码 EOF、图像字节和标注身份是否可信。
- 场景适用性：图像是否与明确选择的正常参考及冻结的 SceneGuard 策略匹配。
- 训练可行性：图像能否读取，数量是否足够，是否存在严重曝光、模糊、纹理等质量问题。
- 正常工况代表性：实际观察到了哪些照明、人员活动和正常作业条件；未观察到的条件不能自动算作已覆盖。
- 生产业务能力：独立测试中的召回率、误报、延迟、场景隔离、恢复与多任务共存能力。

低多样性属于代表性风险，不应自动等同于前三项失败。训练前检查通过只说明允许进入受控训练流程，不代表后两项已经满足。

## 3. 版本化静态场景策略

策略标识固定为 `argus.baseline-quality.scene-static.v1`，质量报告保存 `policy_version`、原始测量值、硬错误和警告，不能只输出一个无解释的布尔值。

适配范围必须由服务端已验证的 `SceneTrainingInput` 决定：

1. 执行共享的 `revalidate_scene_training_input()`，验证服务端推导的工作流、严格 v3 基线及完整身份。
2. 仅这一受控分支允许选择静态场景质量策略。客户端布尔值、任意目录旁存在 manifest、伪造 dataclass 或 `skip_baseline_validation` 都不能授权该策略。
3. 旧目录、旧数据和非场景工作流不能因本次适配自动获得新的训练资格。兼容接口保留原字段时，必须同时解释指标和实际策略，不能把不同重复算法的数值混称为一个权威指标。
4. 低亮度波动和高感知近重复保留测量结果，转为“仅覆盖已观察静态条件”的明确警告，不删除、不改写成多样性充分。
5. 图像不足、损坏、身份不一致、严重逐帧质量缺陷及场景不匹配仍然失败。不能用整组图片“足够静态”掩盖全黑、全白、失焦或无有效场景内容。

该策略不是一次通用阈值调低，也不是跳过质量检查。后续若优化重复指标，应变更指标版本并保留来源与历史解释，不能悄悄使旧报告中的比例变成另一种含义。

## 4. 不改变的数据、审批和发布边界

严格 v3 原有条件继续适用：完整源解码与清洁 EOF、前后 SHA256、PTS 及逐帧清单、样本字节身份、正常性人工复核、明确相机和参考身份、至少两个独立声明并复核的录制会话、整会话分组、至少 100 张训练样本、50 张校准样本和 300 秒有效时间跨度。历史缺失信息保持未知，不能补造硬件源帧号或 PTS。

训练和校准必须来自冻结的不同会话；保留测试会话不进入二者。不得把相邻帧随机拆分成“独立”训练和测试，也不得靠复制图片、人工制造噪声、改变亮度或移动相机来满足数量、多样性或场景条件。真实允许的正常光照变化可以另行采集；机位、焦距、区域坐标变化则需要遵循场景变更流程，而不是当成正常数据增强。

完整校准集不去重、不精选、不以训练抽样上限截断。每张冻结校准图都必须读取并产生有效分数；样本数、有限且有序的分数及严格递增阈值继续校验。若静态数据使校准结果退化，仍应失败或进入明确的未就绪状态，不得为了产出模型而伪造阈值。

质量策略、原始指标、警告和适用范围同时保留在训练结果、作业成功/失败记录、候选模型注册参数及制品清单。重导出、重校准产生新候选时，必须继承源制品的范围限制，并明确标记为“来源条件继承，未重新评估”，不能因派生操作清空警告或获得生产资格。历史源制品缺少报告时保持未评估，不能推断通过；继承不是新数据集、校准完整性或审批的证明。

时间上相邻的图片通常相关。独立会话划分减少了显然的数据泄漏，但不自动证明统计交换性、样本有效独立数或现场误报率。依赖数据的 conformal 方法需要明确处理其依赖结构；本次适配不等于实现了相应论文算法或获得其保证。[Chernozhukov、Wüthrich、Yinchu，COLT 2018](https://proceedings.mlr.press/v75/chernozhukov18a.html)

训练确认仍由有效个人账号执行，自动化不能冒充人工。场景正常性确认、训练确认、场景/模型绑定审批和生产审批仍是不同动作。报告、图像或身份变更后，不能自动沿用旧审核结论。

候选模型仍需原有完整生产验收：baseline v3、完整校准、场景和制品身份绑定、SceneGuard、独立审批、独立异常/负例效果、多任务资源与采样验收、可信签名 soak 以及发布服务的准备、切换、失败保留和对账。现有召回、误报、延迟、覆盖率与 soak 指标不因静态策略降低。训练报告的正常分数等级不能表述为“可直接部署使用”。

## 5. 静止与冻结不能只靠像素判定

完全或高度相似的像素既可能来自合法静态场景，也可能来自冻结、重复或回放。感知哈希、精确字节哈希、亮度变化都只能提供诊断线索，不能单独证明物理相机实时性。

应分别保存源会话/重连代次、采集时间、设备可提供的序号、驱动或媒体 PTS 及其来源。完整解码、PTS 递增与字节一致性证明的是录制和传输证据的一致性，不是“现场一定实时变化”。来源缺少实时性证据时应明确标记未知，而不是为满足静态训练规则伪造结论。需要物理遮挡、移动或现场事件的验证，在条件不具备时保留未测。

## 6. 测试与无人办公室边界

本机只运行普通功能、纯协议和替身测试。真实图片质量分析、视频解码、训练、校准和识别均在授权测试机执行；不改源视频，不将凭据、现场图像或私有验证包上传 GitHub。

无人办公室可验证来源身份、解码完整性、静态正常抽样、质量策略分流、失败重试、审批拒绝以及明确标注的内存模拟变化。模拟移机通过不能替代真实移动相机的验收，正常静态录像也不能产生真实异物/快速物品召回结论。短时间负例不等于满足长期误报或可信 soak 要求。

至少覆盖以下回归不变量：

- 合法且重新验证的 v3 静态样本得到带范围限制的警告，而不是无解释拒绝或“已充分泛化”。
- 旧入口、客户端静态声明、篡改身份、缺失人审、单会话及错误分组不能获得静态策略资格。
- 损坏、严重图像缺陷、场景不匹配、缺失 PTS/EOF 或样本 SHA 改变仍然拒绝。
- 完整校准、个人账号审批和生产 NO-GO 条件不变，候选注册不自动切换运行时。
- 无现场配合的测试结果与真实业务验收分开报告；未运行的 GPU 训练、真实识别和多任务业务回归保持未完成。
